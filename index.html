01 / HOW IT WORKS

两跳链路，从 Agent 到引脚

Agent ↔ 网关走 HTTP（跨网络可达），网关 ↔ 硬件走进程内服务。固件走独立数据面上传，字节不进 AI 上下文。

02 / CAPABILITIES

为硬件开发而生的六个能力

CAP-01

MCP 网关

Streamable HTTP 为主、SSE 兼容兜底；工具动态注册，请求元数据全量落日志。

HTTP :9870SSE 兼容会话管理
CAP-02

串口终端

传统工具手感：GBK/UTF-8 双解码、毫秒级时间戳、DTR/RTS 独立控制、意外断连自动重连。

GBK / UTF-8自动重连HEX 收发
CAP-03

断言测试脚本

serial_script 一次调用跑完整轮 AT 回归：命令 + 期望逐条断言，URC 干扰自动容错，直接给出 PASS / FAIL。

50 步断言失败重试URC 容错
CAP-04

固件通道

Agent 或 CI 直接推送固件（curl 一条命令），AICom 中转落盘并回执 SHA-256，逐字节可校验，单文件最大 128MB。

SHA-256 回执数据面直传
CAP-05

电源控制

USB 继电器断电 / 上电 / 电源循环，CH340 身份校验防串口漂移误控，烧录前断电进 Boot 一气呵成。

电源循环防误控校验通道别名
CAP-06

插件生态

插件即独立 MCP Server：GitHub 仓库直装、市场一键安装、Python 依赖自动自愈，RDA 8909B 烧录插件开箱即用。

独立端点环境自愈仓库直装
